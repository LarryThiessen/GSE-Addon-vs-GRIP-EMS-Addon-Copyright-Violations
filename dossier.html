01

GRIP-EMS ships a dedicated dual-path GSE ingestor — migrate (reads a live installed GSE library) and import (decodes the export string) — and the same operator runs the LazyGrip website that decodes and converts GSE strings server-side. The code

The addon reads GSE's internal on-disk globals directly — GSESequences[0..13][name], GSE.Library, GSEVariables, GSEMacros, GSE_C at Import/LegacyMigrate.lua:57-207,262-395, matching GSE's own layout at GSE/API/Storage.lua:769-782. The code

GRIP fully decoded GSE's !GSE3! table: its importer names every GSE field — Versions/MacroVersions, MetaData.{Author,SpecID,GSEVersion,Checksum,Dependencies,…}, StepFunction, InbuiltVariables, and the 11-key context vocabulary — an "identical key set" to GSE at Import/LegacyImport.lua:24-36,494-916 vs Storage.lua:1059-1071.

Black-box, not copied. The proof it was reverse-engineered rather than lifted: GSE's distinctive artifacts are absent — GSE's ChaCha20 subscriber-content decryptor (GSE/API/Codec.lua) is gone (GRIP has no decryptor and refuses that content); GSE's CBOR delta engine (GSE/API/SequenceDelta.lua) is gone; and GRIP's ReversePriority/Random modes diverge. A copy would have carried all three.

The code

GSE placed an affirmative lock — a "minimal locked proxy… to deny in-memory scraping by third-party addons" at GSE/API/Storage.lua:9-16. GRIP wrote a documented workaround: its own comment at Import/LegacyMigrate.lua:92-99 notes "newer source builds keep the runtime table private," then it reaches into the raw GSESequences SavedVariables on disk at Import/LegacyMigrate.lua:195-207 instead. The bypass exists because GSE hid the data.

Honest boundary. Those SavedVariables are plaintext on the user's own disk, so this is not classic DRM circumvention. Its force is intent and non-consent: GSE said "no scraping," and they engineered past it — and what the workaround reaches is precisely the un-encrypted, licensed creator content (GSE's own encrypted subscriber content, they can't touch).

04

They strip the owner's identifier

On import and on the website, GRIP removes the machine-verifiable ownership linkage GSE stamps on every sequence — the PlatformID record key, the gse.tools source URL, and the integrity Checksum — while keeping the human author label. GSE's own code proves the PlatformID is an ownership handle: it's cleared on duplication so a copy can never resolve to the original's record.

The code

On import, GRIP copies exactly six fields — and PlatformID is not one of them (Import/LegacyMigrate.lua:170-175):

author      = seqObj.MetaData and seqObj.MetaData.Author,
description = seqObj.MetaData and seqObj.MetaData.Help,
specID      = seqObj.MetaData and seqObj.MetaData.SpecID,
updatedAt   = seqObj.MetaData and seqObj.MetaData.LastUpdated,
icon        = seqObj.Icon,
classID     = classID,
-- (no PlatformID; no GSE.Tools identity carried forward)

PlatformID appears zero times in GRIP's entire ~9,000-file tree — confirmed by full scan of all 64 releases (v1.0.4 → v2.3.5). Constant and structural, never a slipped-in build.

That the dropped field is an ownership handle is proven by GSE's own code: it clears PlatformID on duplication at GSE/API/Storage.lua ~L731 — "so the copy and the original never resolve to the same server record" — and preserves it across renames. It is, by design, the field that binds a sequence to its author of record.

07

How closely the result clones GSE

GRIP is a functional and design clone: the same container envelope, a renamed copy of GSE's schema, and — the sharpest point — GSE's signature Priority algorithm reproduced to byte-identical output. Meanwhile the one thing GRIP markets as different from GSE isn't implemented in its engine at all.

The code

The Priority fingerprint. GSE's distinctive triangular N·(N+1)/2 weighted round-robin — for N=3 it emits [1, 1, 2, 1, 2, 3]. GRIP emits the identical order. GSE writes it as a stateful limit/step walk (GSE/API/Storage.lua:2155-2171); GRIP writes it as a clean nested double-loop (Engine/StepFunctions.lua:248-262). Different code, byte-identical behavior — and this weighting isn't platform-mandated, it's GSE's original design choice. GRIP's own v2.3.6 changelog confirms they preserve it: "a Priority loop keeps its weighted pattern instead of flattening to an even split."

Same envelope, renamed schema. Both encode CBOR → raw DEFLATE → Base64 → "!PREFIX!"; a !GSE3! and a !GRIP1! differ only in the CBOR table inside. GRIP renames GSE's keys (Sequences→sequences, StepFunction→stepFunction, InbuiltVariables→resetOn*, …) but keeps the concepts and feature set 1:1 — "GRIP's own code treats the two models as trivially interconvertible." Sataana says it plainly: "what the website is doing (transforming GSE to EMS) the add-on currently does."

The marketed difference isn't real. LazyGrip sells an engine that "holds its place when a cast fails instead of skipping ahead." The shipped engine advances the step on every press (step = step % numS + 1, Engine/StepFunctions.lua) with no cast-success gate anywhere; the only UNIT_SPELLCAST_SUCCEEDED handler in the whole engine is for the talent-swap spell, not the rotation. WoW can't even expose cast-success to secure code. So on the point they claim sets them apart, GRIP behaves exactly like GSE.

What this does & doesn't prove

Established by their words + their code
  • A dual-path GSE ingestor and a public web ingestor, built to target GSE's format directly.
  • A reverse-engineering method, in the developer's own words, using TL's ARR commits and AI.
  • A stated goal of bypassing GSE's protection, and an engineered workaround of GSE's anti-scrape lock.
  • The owner-identifier (PlatformID) dropped on import — 0 refs, all 64 releases — and stripped again server-side by the website, with the gse.tools link and integrity checksum.
  • Full plaintext reproduction of the works on demand.
  • Admitted redistribution of the creators' free, All-Rights-Reserved content across "MANY Discords."
  • GSE's signature Priority algorithm reproduced to byte-identical output.
Not established — do not overclaim
  • Not source-code copying. A full five-subsystem diff found no copied source in any subsystem — it's a reverse-engineered functional/design clone. The Priority match is byte-identical behavior, independent code.
  • Not the AI method as fact. The code can't identify what tool wrote it. The AI-transpilation plan is their stated intent, an allegation for discovery — not a proven mechanism.
  • Not DRM circumvention. The SavedVariables are plaintext on disk; the claim there is intent and non-consent.
  • The human Author name is retained, so this is CMI removal + unauthorized use, not plagiarism.
